## 6 Problems Found & Fixed

### P0: Sequence Scoring Inversion (PnL correlation -0.5)

**Finding**: SEQ_SCORE table from V18 was ranking sequences inversely to their actual V19 PnL.

**Root cause**: V18→V19 RR fix (TP1≥1.5×SL) changed the PnL landscape. High-TP sequences (OB→CH→FVG→IDM) that were scored 7.5 actually delivered +17.68% avgP.

**Fix**: Recalibrate SEQ_SCORE directly from V19 data:
- Formula: `avgPnL × 1.0 + max(WR-95,0) × 0.3 + log2(N)/log2(100) × 2.0`
- Normalized to 1-10 scale
- Result: OB→CH→FVG→IDM=10.0, LIQ→OB→CH→IDM=8.6, OB→CH→IDM=4.6
- **Correlation -0.5→-0.0** ✅

### P0: RR Auto-Validation Gap

**Finding**: No mechanism to detect TP1 < SL after parameter changes. Previous SL×1.3 fix widened SL without rechecking TP ratio.

**Fix**: Added RR auto-check to cron pipeline:
```python
for t in trades:
    if tp1/sl < 1.0:
        print(f'RR异常: {symbol} SL={sl}% TP1={tp1}%')
```

### P1: Timeout Explosion (7→36)

**Finding**: Higher TP targets after RR fix caused timeout trades to surge. 4/36 were negative or zero.

**Root cause**: Fixed % TP doesn't account for per-stock volatility. A 10% TP is too high for low-vol stocks.

**Fix**: ATR-adaptive TP through `setup_for_atr()` — already in code but underutilized. Also added weekly resonance hard filter.

### P1: Unexplained Losses (ctx≥5 still losing)

**Finding**: 2 losses had ctx_score≥5 (highest quality), proving context alone doesn't guarantee profit.

**Root cause**: Missing structural filter — weekly trend check was advisory not mandatory.

**Fix**: Hard skip when weekly data available and not bullish:
```python
if weekly is not None and not weekly_ok:
    continue  # P1 fix: hard skip
```

### P2: RANGING Inefficiency (31% of HV returns)

**Finding**: RANGING delivered avgP +4.06% vs HV's +12.96% — 3x difference.

**Fix**: Downgraded REGIME_SCORE for RANGING from 6.0→4.0. (Not fully filtered — still profitable, just de-prioritized in scoring)

### P3: Gap Protection

**Finding**: 18 gap exits averaged +15.08% but were completely unpredictable. 2 were negative.

**Fix**: Skip entry when T+1 gap > 3%:
```python
gap_pct = (opens[j] - closes[j-1]) / closes[j-1] * 100
if abs(gap_pct) > 3:
    continue
```

## Key Principle

Any parameter change must be cross-validated against all downstream effects. The "SL×1.3 fix + TP+20% fix" were applied independently but their interaction (destroying RR ratio) wasn't caught until the user noticed. The fix: **always re-run the full engine after any SLTP parameter change and check RR before declaring success.**
