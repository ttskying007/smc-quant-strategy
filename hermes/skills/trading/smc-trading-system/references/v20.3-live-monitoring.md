# V20.3 Live Price Monitoring — 实时价格监控+SL/TP卖出信号

## Overview

New page `/live` on the SMC frontend (port 8890) that provides real-time stock price monitoring with automatic SL/TP sell signals.

## Architecture

```
v19_picks.json (265 stocks, each with regime/sl_initial_pct/tp_tiers/entry_price)
        │
        ▼
/api/live-prices (Python endpoint)
        │
        ├── Strips .SH/.SZ/.BJ → pure codes for Hubble API
        ├── Batch fetches real-time quotes (500 codes/request)
        │     GET http://43.167.234.49:3101/api/v2/cnstock/securities?codes=...
        │     Headers: X-API-Key: 123456
        │     Fields: code,name,price,chgPct,open,high,low
        ├── Per-stock SL/TP computation:
        │     sl_price = entry_price × (1 - sl_pct/100)
        │     tp_price = entry_price × (1 + tp_tiers[0]/100)
        │     pnl_pct = (current - entry) / entry × 100
        └── Five-level status determination:
              SL_HIT:      current ≤ sl_price
              TP_HIT:      current ≥ tp_price
              SL_CLOSE:    current ≤ entry × (1 - sl_pct×0.7/100)
              TP_CLOSE:    current ≥ entry × (1 + tp_tiers[0]×0.8/100)
              HOLDING:     everything else
              NO_DATA:     current_price == 0
        │
        ▼
/live page (HTML + JS)
        ├── Auto-refresh every 30s via <meta http-equiv="refresh" content="30">
        ├── JS fetch('/api/live-prices') on page load
        ├── Color-coded table with columns:
        │    代码 | 名称 | 入场价 | 现价 | 涨跌 | PnL% | SL | SL价 | TP | TP价 | 状态 | 信号
        ├── Status colors:
        │    SL_HIT: red blinking ("卖出" badge)
        │    TP_HIT: green blinking ("卖出" badge)
        │    SL_CLOSE: orange ("⚠接近SL" badge)
        │    TP_CLOSE: dark green ("接近TP" badge)
        │    HOLDING: blue
        └── Summary bar at bottom:
              持仓: N | ⚠接近SL: N | 接近TP: N | 🔴SL命中: N | 🟢TP命中: N
```

## Hubble API Integration Pattern

```python
# In Handler class:
HUBBLE_BASE = "http://43.167.234.49:3101"
HUBBLE_HEADERS = {"X-API-Key": "123456", "Content-Type": "application/json"}

@classmethod
def fetch_live_prices(cls, codes):
    """codes: list of pure numbers (no exchange suffix)"""
    import urllib.request
    url = f"{cls.HUBBLE_BASE}/api/v2/cnstock/securities?codes={','.join(codes)}&fields=code,name,price,chgPct,open,high,low,volume"
    req = urllib.request.Request(url, headers=cls.HUBBLE_HEADERS)
    with urllib.request.urlopen(req, timeout=8) as resp:
        data = json.loads(resp.read())
    # Parse response - handles both dict and list formats
    for item in data.get('data', data if isinstance(data, list) else []):
        code = str(item.get('code', ''))
        result[code] = {'price': float(item['price']), ...}
    return result
```

**Code format**: MUST strip exchange suffixes. `600519.SH` → `600519`. Max 500 codes per request.

## Non-Trading Hours Behavior

Hubble API returns empty data when market is closed (weekends, nights). The endpoint handles this gracefully:
- `NO_DATA` status for all stocks
- `error_msg = 'Hubble API无数据 (可能非交易时段或API故障)'`
- Frontend shows "API错误: ... (可能非交易时段)" if fetch fails entirely

## Key Implementation Details

- `Handler.fetch_live_prices` is `@classmethod` so it works from both instance methods and static contexts
- Results sorted by status priority (SL/TP hits first) then by PnL descending
- Batch fetching avoids rate limits with 500 codes per call
- SL/TP price computation uses the stock's regime-specific parameters from picks
- The `tpTiers` field is an array of all TP tier percentages (e.g., [4.0, 8.0, 13.0, 24.0])
- Only `tpTiers[0]` is used for the sell signal threshold
