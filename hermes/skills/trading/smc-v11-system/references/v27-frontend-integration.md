# V27 Frontend Data Integration Lessons

## Core Problem

V27 trades/picks have different field names and semantics than V25/V24. When V27 data replaces older versions as the default, every frontend page that reads trades/picks breaks silently.

## Critical Field Mismatches

### 1. Win detection: no `won` field

V25 trades have `won: true/false`. V27 does NOT — use `pnl_pct > 0` instead.

**Fix pattern** — module-level helper:
```python
def is_winner(t):
    """True if trade is winning. V27: pnl_pct>0; legacy: 'won' field."""
    if t.get('engine','') == 'V27_STRICT':
        return t.get('pnl_pct', 0) > 0
    return t.get('won', False)
```

**Replace ALL** `t.get('won')` with `is_winner(t)` across the entire frontend.

### 2. Exit reason case: uppercase in V27

V25: `'SL_hit'`, `'TP_hit'`, `'trailing'`, `'timeout'`
V27: `'SL_HIT'`, `'TP_HIT'`, `'TIMEOUT'`

**Fix**: Normalize to uppercase on read:
```python
exits = Counter((t.get('exit_reason','?') or '').upper() for t in trades)
sl_pct = exits.get('SL_HIT', 0) / n * 100
```

### 3. No `market_state` / `regime` in V27

V27 trades don't have market state classification. Fall back to `engine` field or `'?'`.

### 4. K-line signals: V27 recent_signals only has zones

`v27_recent_signals.json` stores only OB, BPR, OTE zones (generated by `extract_recent_zones()`).
It does NOT contain: FVG, BOS, CHOCH, MSS, SWEEP, PO3, Pinbar, BreakerBlock.

**Do NOT use V27 markers for chart rendering** — always run `detect_sigs(data)` for the rich signal set.
V27 data should only be used for the trade table below the chart.

### 5. Signal type name mismatch

V27 types: `'OB'`, `'BPR'`, `'OTE'` (singular, no direction)
Frontend SIG_FAMILY keys: `'OB_Bull'`, `'BPR_Bull'`, `'OTE_Bull'`

If mapping V27 markers to frontend, MUST use:
```python
type_map = {'OB':'OB_Bull','OTE':'OTE_Bull','BPR':'BPR_Bull', ...}
```

### 6. Picks have `state` field

V27 picks generated by `generate_picks()` have:
- `state`: 'ACTIVE' or 'HISTORICAL'
- `bars_from_end`: distance from last entry

Monitor/选股 page must filter by state, NOT by date string comparison.
Legacy date filtering (`entry_date >= today`) fails because V27 pick dates are historical.

**Monitor dedup**: show ONE best pick per symbol (highest `score`), limit to 200:
```python
best_by_sym = {}
for p in active:
    sym = p.get('symbol','')
    if sym not in best_by_sym or p.get('score',0) > best_by_sym[sym].get('score',0):
        best_by_sym[sym] = p
picks = sorted(best_by_sym.values(), key=lambda p: -p.get('score',0))[:200]
```

### 7. Trade duplicates from zone-type expansion

One BOS event generates up to 3 setups (OB + OTE + BPR). The backtest page shows these as separate trades with identical entry_date/entry_price.

**Fix**: Dedup by `(symbol, entry_date[:10], round(entry_price, 2))` before display.

## Integration Checklist

When switching to a new V27 full scan:

- [ ] `is_winner()` replaces all `t.get('won')` across all pages
- [ ] Exit reasons normalized to uppercase
- [ ] K-line uses `detect_sigs()` for signals, V27 only for trades
- [ ] Monitor uses `state` field, not date filtering
- [ ] Monitor dedup by symbol (best score)
- [ ] Backtest dedup by (symbol, date, price)
- [ ] Backtest limited to 100 rows
- [ ] Cumulative PnL sampled to 2000 points
- [ ] Memory cache enabled for trades (61MB → 0.3s)
- [ ] ver_map lazy-loads non-V27 versions
- [ ] Version dropdown defaults to V27
