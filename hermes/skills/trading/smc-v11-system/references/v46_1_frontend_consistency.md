# V46_1 前端一致性与重跑链路

## 适用场景
- 当前活动版本是 V46_1，但前端提示“当前版本暂不支持重跑”。
- `picks.json` 为空，前端 `/api/picks` 为空列表。
- `/docs` 页面内容与活动版本不一致。
- 需要排查“止损偏多、交易少、选股为空”时的链路缺口。

## 排查顺序
1. `report.json`：先确认当前版本真实指标，而不是看前端标题。
2. `picks.json`：确认是否真有 active picks。
3. `/api/picks`：确认前端 API 读到的是否是同一文件。
4. `_api_reselect` 的 `engine_map`：确认版本到引擎脚本有重跑入口。
5. `/docs` 内联内容：确认版本名、报告文件、说明文字是否同步。

## 常见坑
- “版本激活”不等于“重跑已支持”。版本检测和重跑映射是两条独立链路。
- `picks.json` 为空时，不要自动回退历史最佳选股，否则会造成前端数据错位。
- 文档更新不能只改输出文件名，必须同步页面内联文案和标题。
- 止损偏多时不要先调参数；先分诊：信号识别、入场点、组合顺序、过滤契约、出场逻辑。

## 经验规则
- 若交易数少但平均盈利偏高，优先怀疑过滤过严或只保留了高质量样本。
- 若用户问“为什么止损多”，默认按三段排查：信号是否正确 → 是否在正确点入场 → 是否存在过早出场。
- 当前版本的前端应明确展示“无 active picks”，不要静默空白。
