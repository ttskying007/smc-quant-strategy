# V69 五项遗漏门禁验证教训

## 触发场景

当一个候选 SMC 引擎语义门禁通过、但全量效果失败时，不要只继续调形态阈值。需要把“遗漏机制”拆成可验证的独立门禁，并分别做：单项效果、组合效果、同股随机方向边际、是否存在事后污染。

## 本次关键结论

基于 V68 全量 `1657` 笔交易测试五项遗漏机制：

1. 市场状态/时间窗口开关
2. Zone 时效门禁
3. SSL sweep 到入场的同一段故事时效
4. CHOCH 后 reaction / follow-through 确认
5. 多周期确认代理层

结果证明：五项不能机械叠加。五项全开只剩 `25` 笔，WR `36.00%`，Avg `-0.646%`，SL `60.00%`，方向边际 `0/6`，不是可交易规则。

真正改变效果的是：

- 市场状态/时间窗口开关
- RR 质量门禁
- 真实多周期确认的方向，但不能用日线出场后的 proxy 替代

## 有效桶与限制

| 组合 | 结果 | 处理 |
|---|---|---|
| `2025H2 + RR>=2` | 72 笔，WR `62.50%`，Avg `+4.187%`，SL `37.50%`，同股随机边际 `6/6` | 有方向边际，但未达生产线 |
| `2025H2 + 日线MTF proxy + RR>=2` | 56 笔，WR `80.36%`，Avg `+6.110%`，SL `19.64%`，同股随机边际 `6/6` | 只能证明真实 60min 确认值得做；不能直接上线 |
| 五项全开 | 25 笔，WR `36.00%`，方向边际 `0/6` | 拒绝作为规则 |

## 必须新增的候选验证顺序

1. 先基于失败版本交易明细做独立遗漏门禁审计。
2. 每个门禁先单项测试，再做组合搜索，避免“全部叠加反而破坏边际”。
3. 任何看起来通过的子集，都必须重跑同股票随机方向边际。
4. 如果组合使用了 `hold_bars`、`exit_reason`、“未即时止损”等出场后字段，只能标记为 proxy，不能作为生产规则。
5. 通过 proxy 发现方向后，必须回到入场前可见数据重建规则，例如真实 `60min/15min` reclaim、follow-through、缩量回踩/放量反推。
6. 下一版候选必须重新全市场扫描/回测，不能只过滤旧交易明细后发布。
7. 晋级时必须与当前生产版本同周期对比，不能只与失败候选对比。

## V69 推荐候选方向

`V69 = V68日线POI + 市场状态开关 + RR>=2 + 真实60min确认`

硬门禁：

- 日线 strict registry 只输出 POI/地图，不直接确认入场。
- 真实入场确认必须发生在 entry 前，禁止使用 `exit_reason`、`hold_bars` 等未来信息。
- FVG absent / sweep 时效这类短弹特征只能作为辅助，不是主因。
- 重新跑语义门禁、方向边际门禁、效果门禁、生产对比门禁。
