# V37 流动性区域检测 — 会话记录 (2026-05-09)

## 架构设计

V37在V36核心基础上增加了三层架构:

```
Layer 1: 流动性区域检测 (liquidity_v37.py)
  - 三级摆动点: micro(3)/meso(8)/macro(20)
  - 聚类摆动点 → BSL/SSL流动性池
  - 密度评分(越多摆动点越密集 = 流动性越大)
  
Layer 2: 猎杀追踪
  - BSL池被价格上穿 = 空头止损猎杀
  - SSL池被价格下穿 = 多头止损猎杀
  - 猎杀后1-3根K线内反转 = 成功猎杀
  - 猎杀后未反转 = 假突破/趋势延续

Layer 3: ATR自适应序列窗口
  - 高波(ATR>3.5%): tight[3]/medium[4]/loose[6]
  - 中波(1.5-3.5%): tight[4]/medium[6]/loose[8]
  - 低波(<1.5%): tight[5]/medium[8]/loose[12]
```

## 测试过程

### 1. V11.2信号检测修复 (9项)
1. FVG: +C2实体要求(>=60% ATR), 趋势对齐收紧至0.5%
2. OB: 完全重写为真实ICT OB (last opposite candle+2+ impulse)
3. Sweep at_swing: 按时间窗口(8根)过滤, 非全局最后5个价格
4. LiquidityVoid: gap检测替代宽幅低量K线
5. MSS: 窗口5→3, 阈值0.3%→0.2%, strength上限6→4
6. CHOCH/MSS: MSS=微观(3根窗口), CHOCH=结构转换(摆动点级)
7. IFVG/BPR/BreakerBlock: strength/confidence动态计算
8. OTE: 0.5-0.68区间+量缩验证
9. PO3: ACC阈值ATR%自适应

结果: WR=86.0%, RR=3.46x, PF=30, P&L=+2.41%
(修复前: 84.0%/3.09x/24/+2.08%)

### 2. V37纯流动性猎杀模式测试
- 50只股票: 162次猎杀, 其中43次(27%)在5根K线内产生FVG
- 纯ICT Sweep→FVG模式: WR=15.6%, RR=15.76x, PF=2.9
  - 低WR原因: A股日线gap使猎杀后的反转经常被gap隔夜止损
  - 猎杀位置在日线级别精度不够(oscar发生在盘中)

### 3. V36核心+流动性过滤测试
- 200只股票: 674笔FVG交易, WR=35.9%
- 有猎杀(431笔): WR=34.6%
- 无猎杀(243笔): WR=38.3%  
- 结论: 流动性猎杀上下文不改善A股日线FVG交易的WR

### 4. V36 vs 复现版本差异追踪
原始V36测试(86%) vs 复现代码(36%)的差异根因:
1. V36使用Scout-only序列过滤器(只接受单一FVG)
2. 成交量检查(FVG中K线量>=30日均量70%)
3. FVG中K线必须阳线(c>o)
4. exit_price = max(sl, bar['l']) (gap下穿取低点)
5. 多TF周期过滤器(微/中/宏趋势组合)

即使完全复制V36过滤器, WR也只到36-40%。差异很可能来自V11.2修复后FVG信号变化。

## 核心结论

1. V36紧SL(0.3%)+保本trailing是A股日线唯一最优路径
2. 流动性猎杀在日线层面无法有效利用(gap特性)
3. V11.2信号修复提升WR从84%→86%, RR从3.09→3.46
4. 复杂化(多信号组合/共振/链码/POI)不改善基础方案
5. 结构性TP(swing_high, WR=96%, 78%交易使用)是唯一突破

## 阻碍进一步改进的因素

1. Hubble API 401: 60min/周内/ETF数据不可用
2. 缺少intraday数据: 真正的ICT猎杀→反转需要15min/5min
3. A股日线固有特性: 涨跌停板、T+1、集合竞价
