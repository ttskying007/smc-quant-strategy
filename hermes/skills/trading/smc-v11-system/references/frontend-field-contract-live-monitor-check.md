# 前端字段合同：选股页/实时页显示异常排查

## 适用场景

用户反馈选股页或实时页出现字段空值，例如：
- 选股页缺少“选股日期”“加入日期”列
- 页面下方引擎/合同区 `zone` 为空
- 实时页“成本线”“波动”为空

## 最小排查顺序

1. **先确认当前用户任务，不要被压缩上下文中的 Active Task 带偏**
   - 压缩摘要只是背景；最新用户消息优先。
   - 如果最新任务是前端字段修复，不要继续旧的回测/策略迭代任务。

2. **先查 API 字段合同，再改页面**
   - `/api/picks` 应至少检查：`pick_date`, `join_date`, `zone`, `zone_type`, `zone_low`, `zone_high`, `cost_line`, `smart_money_cost`, `volatility_pct`。
   - `/api/live-prices` 应至少检查：`pickDate`, `joinDate`, `zone`, `zoneType`, `zoneLow`, `zoneHigh`, `costLine`, `cost_line`, `volatilityPct`, `volatility_pct`。
   - 如果 API 字段完整，优先检查页面 JS/HTML 字段名映射或服务缓存，不要重跑策略脚本。

3. **用浏览器验证实际渲染**
   - 打开 `/monitor` 核验表头和首行：选股日期、加入日期、Zone、成本线、波动。
   - 打开 `/live` 核验：选股日期、加入日期、买入日期、成本线、Zone、波动。
   - 浏览器快照优先于只看 JSON；用户反馈的是页面显示问题。

4. **只做最小前端字段修复**
   - 修改 `_apply_smc_field_contract()` 或对应页面字段读取时，保持语义不变，只补别名/兜底。
   - 不要顺手修改生产门禁、回测参数、候选池或策略版本。

5. **如果误触策略逻辑，立即回滚并恢复数据**
   - 检查相关脚本中是否遗留非本任务字段或门禁，例如临时 `v103a_*`、`risk_pct>=...`。
   - 重新运行原生产脚本恢复输出文件，并再次核验生产统计回到预期。

## 验收标准

- `/api/picks` 和 `/api/live-prices` 对上述字段缺失数为 0。
- `/monitor` 页面实际显示选股日期/加入日期，Zone/成本线/波动不为空。
- `/live` 页面实际显示成本线/Zone/波动不为空。
- 无无关策略脚本差异或生产门禁残留。
