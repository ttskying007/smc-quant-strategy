# Reversal SMC State Machine: Semantic Acceptance Before Backtest

## Trigger
Use this workflow when rebuilding or validating a bullish SMC reversal scanner. The objective is signal semantics first—not win rate, RR, stop placement, holding period, external events, or selector tuning.

## Canonical three-layer causal chain

```text
L1: confirmed external SSL
    -> later wick sweep below SSL
    -> close reclaims above SSL

L2: reversal structure takeover
    -> post-sweep close accepts above a pre-sweep confirmed lower high
    -> bullish displacement (not wick-only)
    -> causal Demand OB and/or FVG from that displacement leg

L3: POI lifecycle
    FRESH -> FIRST_TOUCH -> RECLAIM -> HOLD -> ELIGIBLE_NEXT_BAR
```

For reversal-only classification, establish bearish context before sweep: the SSL is a lower low relative to a prior confirmed low, and the reference high to break is a lower high relative to a prior confirmed high. Do not call a continuation BOS a reversal CHOCH/MSS.

## Required invariants

1. A pivot is usable only after all right-side confirmation bars complete; sweep occurs later.
2. The broken high is confirmed before sweep; require close acceptance, not a wick.
3. Displacement is post-sweep, has a non-wick bullish body, and generates the FVG/leg; a generic later FVG is invalid.
4. An OB, when used, is the last bearish candle within the displacement leg and strictly before the break bar. Never use the break bar or an arbitrary historical bearish candle.
5. A FVG may complete on the CHOCH closing bar, but only when generated by the post-sweep displacement sequence.
6. First touch is final: breach of zone low cancels; no reclaim of zone high cancels; later touches never revive a zone.
7. Reclaim is reaction, not entry. Require one completed hold/confirmation bar, then use the next unobserved bar as entry identity.
8. Allow one active chain per symbol; a new SSL sweep supersedes old live state; allow at most one `symbol + entry_date` BUY identity.

## Required fields

```text
symbol, timeframe,
ssl_pivot_time, ssl_confirmation_time, sweep_time, sweep_low,
pre_sweep_reference_high_time, choch_time,
displacement_start_time, displacement_end_time,
ob_time, fvg_time, zone_low, zone_high,
first_touch_time, reclaim_time, hold_time, entry_time,
invalidated_time, cancel_reason, event_log
```

Allowed terminal statuses: `VALID_CHAIN`, `CANCELLED_CHAIN`, `EXPIRED_CHAIN`.

## Acceptance order

1. Generate full-universe chains without reading PnL, exits, returns, stops, targets, or trade files.
2. Assert full-universe timing, OB-anchor, pristine-touch, and duplicate-entry invariants.
3. Export bounded OHLC windows for valid chains, failed first-touch reclaim, and zone-invalidated chains. For valid chains export completed bars only through HOLD; entry remains a next-bar identity so no completed entry-bar outcome is inspected.
4. Only semantic plus visual acceptance may authorize a separately frozen strict T+1 replay.

## Implementation and independent-audit additions

### Do not repeatedly re-arm the same SSL

Keep a per-symbol ledger of swept confirmed SSL pivots. Once a pivot has opened a sweep chain, later dips below the same old SSL cannot create new chains. Without this, an old pivot repeatedly re-arms and inflates terminal-state volume with unrelated micro-dips.

### Terminal-state audit must use the actual terminal bar

`CANCEL_ZONE_INVALIDATED` can occur either on the first-touch bar **or after a successful reclaim during the required HOLD bar**. Independent audit must evaluate the OHLC at `invalidated_time`, not assume `first_touch_time` is always the invalidation bar.

For a successful first touch, `first_touch_time == reclaim_time`; timing checks must assert equality rather than incorrectly require strict ordering between them.

### Independent raw audit performance must not weaken coverage

Group records by symbol and load each source-local raw file once. Do not use `cache.setdefault(symbol, load_raw(symbol))`: Python evaluates the default argument eagerly and will repeatedly decompress the file even when cached. A process pool is valid for per-symbol raw lifecycle reconstruction provided every worker receives only no-outcome chain metadata plus same-source OHLC.

## Pitfalls

- An independent Oracle that reproduces identity tuples proves implementation consistency, not SMC semantic correctness.
- No future data is necessary but insufficient: a wrong POI, reused zone, or continuation misclassified as reversal can still create an honest but invalid backtest.
- Never repair wrong semantics with event/news overlays, narrower windows, SL/TP/hold tuning, or post-result candidate deletion.
