# 数据源就绪与冻结策略本体的边界

## 适用场景

当外部/PIT原始数据缓存补全、接口恢复、或来源覆盖修复后，防止将“数据可用”误判为“已经济失败的旧策略可以重开”。

## 两个必须分离的结论

- **数据资格**：逐文件验证日期、来源、交易所/标的、字段、最小行数、年度覆盖，以及PIT发布时间。
- **策略资格**：在固定预注册语义下完成结果盲种子、独立原始数据Oracle、一次严格T+1冻结回放，并通过经济与逐年门禁。

数据资格通过不能覆盖策略资格失败。

## 操作规则

1. 物理审计缓存，不能以文件数或三点探针替代：逐文件验证元数据和行数，按年输出有效/无效日期。
2. 读取旧策略的冻结决议：
   - `CLOSED_UNAVAILABLE`：仅当原先没有经济结论且覆盖/PIT契约已修复，才允许从原预注册链路重启。
   - `CLOSED_ECONOMIC`：即使缓存后续完整，也禁止重开；不得改变阈值、窗口、止损、目标、持有期、年份或标的子集。
3. 输出no-write对账工件，同时报告覆盖、旧因果语义、冻结指标、逐年结果、T+1和明确策略状态。
4. 对经济关闭本体，保持 `EMPTY_BOOK`，不得生成种子、参数搜索或写入scanner/watchlist/frontend。

## 已验证案例（2026-07-24）

官方SH/SZ融资融券缓存经逐文件审计，各有860个有效日期文件，2023/2024各242日、2025各243日。对应的“前日融资余额增加→SSL sweep→确认CHOCH→Demand reclaim→下一开盘”本体已完成独立Oracle和一次严格T+1冻结回放：n=4508、WR=31.3443%、AvgNet=-0.1189%、PF=0.9658；2023与2024平均净收益为负。它是 `CLOSED_ECONOMIC`，因此缓存完整不能授权策略变体。
