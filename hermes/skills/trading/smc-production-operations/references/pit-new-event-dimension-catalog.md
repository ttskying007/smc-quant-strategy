# PIT 新事件维度：先建目录、后定义策略

## 适用场景

已有 OHLCV、量能、既有公告事件家族或某一条因果链已经冻结失败，但仍可使用完整、带发布时间戳的公告元数据探索**不同的公司治理/资本行为信息维度**。

这不是为已关闭的价格结构或旧事件家族加筛选条件；它是新本体的前置数据资格审计。

## 两阶段纪律

1. **只建 source catalog（结果盲）**
   - 读取字段仅限：`symbol`、公告 ID、公告日、发布时间、标题。
   - 禁止读取任何价格、成交量、SMC 结构、seed、交易、PnL、止损、目标或退出数据。
   - 覆盖全量、已声明的股票宇宙和完整决策年度；每个请求必须抓完分页。任何 HTTP 失败、页上限截断、缺失发布时间都会使目录不合格，不能进入策略定义。
   - 同一 `symbol + announcement_id` 去重，并输出逐年事件数、唯一股票数、失败清单与完整性结论。

2. **独立语义审查后才可预注册策略**
   - 标题命中只是候选目录，不是经济事件本身。
   - 对公司治理/员工权益类事件，排除解禁、上市流通、回购注销、行权/归属、法律意见、财务顾问意见、调整、修订、终止等生命周期/中介文件。
   - 先冻结“什么是原始事件”和 PIT 发布时间规则；再定义一条不同的事件→SMC 因果链；最后才走 outcome-blind seed → 独立 identity oracle → 单次 frozen strict-T+1 replay → 独立指标审计。

## 反模式

- 用公告标题匹配结果直接回测或以事件数量高为有效性证据。
- 因旧 ontology 未达门槛而改其窗口、阈值、止损、目标、持有期、年份或股票集合。
- 把公告列表中包含“限制性股票”等词的解禁、注销、法律文件误当作新的股权激励承诺。
- 用“数据不完整”作为停掉研究的理由；正确做法是在已声明、完整的可用范围内做 source-isolated、明确标注的研究，但不能伪装成全历史生产结论。

## V608 可复用的实现检查

以股权激励/限制性股票/股票期权/员工持股作为新目录时，运行前应确认：

- 宇宙从每日缓存文件名派生，而非从旧选股/交易产物派生；
- 逐标的分页拉取、重试有限且失败可见；
- `fetched_hits >= total_hits` 才算该标的完整；
- `notice_date` 与 `publication_time` 同时存在；
- 目录构建进程可后台运行，完成前不得打开任何后验结果。

该步骤的产出只能是 `SOURCE_CATALOG_COMPLETE__...SEMANTICS_REVIEW`，不是策略通过或生产授权。
