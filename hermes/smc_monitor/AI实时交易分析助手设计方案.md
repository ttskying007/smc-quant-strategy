# AI 实时交易分析助手 —— 设计方案

> 版本：v1.0（2026-09-08）
> 定位：在既有 SMC 量化系统之上，新增一个**可对话、可实时盯盘、可复盘、可质疑策略**的 AI 交易分析助手。
> 目标：辅助（并在受控模式下代理）**快速完成资本初期积累与盈利**，同时反向驱动策略迭代。
> 原则：**轻量、灵活、可调整、可优化、可回滚**。不重构现有策略引擎，只在既有数据/执行之上加一层"AI 决策与对话层"。

---

## 一、设计核心思想

现有系统已经能稳定产出：
- **选股信息**：`paper_ledger.json`（信号组合、信号日期、TP1/2/3/4、SL1/2、stage、adx、v_ratio、position_pct、sub_signals）
- **逐笔回测**：`handover/最新回测数据/逐笔交易全明细.csv/json`（每笔的 buy/sell 价、日期、signal_chain、r20、rank、MFE/MAE、exit_reason）
- **实时价格**：`/api/live-prices`（当前价、昨收、今开、量）
- **受控 Shadow**：`shadow_status.json`（PF、MDD、kill switch）
- **回测引擎**：`/api/backtest/run`、`core.execution.simulate`

AI 助手不重复造轮子，而是**作为"决策者/复盘者/质疑者"**，消费这些数据，形成独立判断，与规则引擎互为校验。

### 关键设计取舍

| 取舍点 | 选择 | 理由 |
|---|---|---|
| 独立进程 vs 并入 smc_unified | **独立轻量进程**（`ai_assistant.py` + 前端插件） | 不破坏生产、可独立启停/回滚 |
| AI 是否直接下单 | **否（v1）**；只出"买卖建议 + 置信度 + 风险"，用户/受控代理确认 | 资本初期，先验证 AI 判断质量再放开自动执行 |
| 单一模型 vs 多角色 | **多角色同进程**（分析师/操盘手/风控官/策略质疑者） | 架构灵活，角色可增删 |
| 状态持久化 | **JSON 账本 + 对话历史文件** | 与现有系统一致，可审计、可回滚 |
| 是否读全市场 | **否**；只关注候选/持仓/关注池 | 轻量、聚焦 |

## 二、目标与不做什么

### 目标（快速资本初期积累）
1. **帮用户快速判断**：今日哪些候选可以买、买多少、止损止盈在哪、最大回撤容忍。
2. **实时盯盘**：持仓出现异常（破 SL、逼近 TP、量价背离、停牌、涨跌停）时主动预警。
3. **复盘**：每笔交易结束后自动归因（做对了什么、做错了什么、与回测预期差多少）。
4. **策略迭代**：发现"规则引擎的盲区 / 过度过滤 / 假信号"并倒推给策略层。

### 明确不做（v1 边界，保持轻量）
- 不直接连券商下单（v1）；只输出可执行的"订单建议 JSON"，由现有 `paper_sim`/`core.execution` 语义校验。
- 不做全新多周期/新指标重算（复用现有 `core.execution`/`core.structure`）。
- 不写回用户金额之外的虚拟杠杆（风控硬约束）。

## 四、模块设计

### 4.1 数据接入层 `DataIngest`（读取层，只读）
从既有文件/API 读入，归一化成 AI 可用的"候选画像"。

**输入源与画像字段：**

| 源 | 画像字段 |
|---|---|
| `paper_ledger.json` | code/name/signal_combo/signal_date/valid_from/entry_price/tp1..tp4/sl1..sl2/stage/adx/v_ratio/position_pct/sub_signals/rank_score/status |
| `handover/最新回测数据/逐笔交易全明细.json` | 该 code 的历史信号 chain、历史 buy/sell、net_pnl_pct、mfe_r/mae_r、rr_exit、IS/OOS 分段 |
| `/api/live-prices` | 现价/昨收/今开/量/涨跌停距 |
| `shadow_status.json` | 事件腿受控 PF/MDD/kill |
| `run_status.json` | 数据新鲜度/四层 complete |
| `config.py` | 账户初始资金、单笔风险、最大持有、滑点 |

**输出（每个候选一个"画像 dict"）**：`{code, name, 现价, 入场参考, TP/SL 网格, 信号组合, 触发信号链, 触发时间, 组合名, 该信号历史回测: {n, avg_net, wr, pf, mfe/mae}, 市场状态, 数据新鲜度}`。

> 所有画像只读；AI 判断绝不写回策略核心。

### 4.2 决策核心 `JudgeEngine`（多角色 + 置信度打分）

**角色（可增删/调权重）：**

| 角色 | 职责 | 输出 |
|---|---|---|
| **分析师** | 对每个候选，结合"当前信号 + 该信号历史回测分布"判断是否值得参与 | `buy_score 0-100` |
| **操盘手** | 决定仓位比例（基于风险距离、流动性、账户余额、与历史仓位相关性） | `position_pct` |
| **风控官** | 硬约束：单票≤X%、当日新开≤N、组合MDD≤10%、接近涨停不追、数据不新鲜不买、同信号同日去重 | `block / allow + 原因` |
| **质疑者/策略批评** | 反向质询：该信号是否历史样本太少？IS/OOS 是否背离？是否追高？ | `challenge[]` |
| **复盘者** | 对每笔已平仓交易做归因 | `postmortem` |

**决策流程（轻量管线）：**

```
候选画像
  → 数据新鲜度门控（fail → 丢弃，标注"数据过期"）
  → 风控官硬约束（不达标 → block，记录原因 → 进漏斗）
  → 分析师打分 buy_score（结合该信号历史回测的 IS/OOS 分层）
  → 操盘手定仓（position = min(预算/风险距离, 单票上限, 账户可用, 历史同信号平均仓位)）
  → 汇总：{建议, 置信度, 建议仓位, 止损, 止盈, 风险, 质疑列表, 漏斗原因}
```

**置信度打分公式（可调）：**
```
buy_score = w1*该信号历史avg_net_z + w2*WR_z + w3*PF_z
          + w4*样本量对数(保底) + w5*新鲜度 + w6*市场状态
          - w7*追高惩罚(现价距入场gap过大) - w8*样本过小惩罚
```
权重 w1..w8 放 config，默认一套，可逐周调。**轻量核心：不打分选股，只对系统已选出的候选做"可买性分级"** —— A 级可买 / B 级观察 / C 级不碰。

### 4.3 盯盘循环 `Monitor`
- 复用 `/api/live-prices`（已有 Sina 实时）。
- 频率：交易时段每 30~60 秒轮询候选+持仓。
- 触发预警：
  - 现价跌破 SL1 / 逼近 SL（进入 X% 内）→ 预警"结构失效临界"
  - 现价逼近 TP1/TP2 → "目标临近，考虑是否减仓"
  - 放量 + 破关键位 / 涨跌停封死 / 停牌
  - 与回测预期 MFE 差太大（入场 N 日后仍无 0.5R 浮盈）→ "假信号嫌疑"
- 每条预警带时间戳 + 触发依据，写入 `ai_alert_log.json`。

### 4.4 对话会话 `ChatSession`
- 通过现有 HTTP 加一个 `/ai` 页面 + `/api/ai/chat` 接口（或独立 WS）。
- AI 能：
  - 回答"今天哪些可以买？为什么？"
  - 解释某个信号的触发链（哪些信号、何时、组成什么组合）
  - 展示该信号历史回测情况（IS/OOS、胜率、盈亏比、最大回撤）
  - 被用户追问"这个凭什么？"
  - 主动质疑策略（读数据后提出"这条规则可能过度过滤/可能假信号"）
- 对话上下文：当前画像 + 该 code 近 N 笔历史 + 近 N 日对话摘要。

### 4.5 策略质疑/反馈 `Feedback`
- 自动统计漏斗：`今日候选 → 各层被拒数量 → 拒因分布`（复用 run_status / selection_result）。
- 异常检测：某阶段触发次数跌出"历史均值±2σ" → 自动向用户报告"是市场结构变了还是逻辑/数据 bug"。
- 输出 `ai_strategy_feedback.json`：给策略层的可执行建议（如"事件腿 ADX 过滤疑似过严，近 20 日被拒 N 笔"）。

## 五、数据流与持久化

### 数据流（单向只读 → 策略）
```
策略产物(ledger/backtest/live)
   └→ AI 读取 → 生成画像 → 决策/盯盘/复盘/质疑
         └→ 输出建议JSON(不写策略核心)
```
AI 的任何输出都不回写 `paper_ledger.json`、`current_scanner_result.json` 等策略源（保持生产不变量）。

### 持久化文件（全部 gitignore，可审计）
| 文件 | 内容 |
|---|---|
| `ai/ai_ledger.json` | AI 每笔"建议/实际"记录（建议日、建议仓位、置信度、后续 MFE/MAE、是否按建议执行） |
| `ai/ai_alert_log.json` | 盯盘预警历史 |
| `ai/ai_chat_history.jsonl` | 对话历史（可回滚、可复盘 AI 自己） |
| `ai/ai_strategy_feedback.json` | 策略质疑输出 |
| `ai/ai_decision_funnel.json` | AI 决策漏斗（今日候选→分级→各拒因） |

> 所有 AI 状态独立于策略，**删除/禁用 AI 不影响策略生产** —— 满足"可回滚、轻量"。

## 六、资金与风控（针对"快速资本积累 + 快速挣钱"）

### 6.1 账户模型（可设置）
```
config: {
  "initial_capital": 100000,       # 用户可设
  "risk_per_trade_pct": 0.01,      # 单笔风险 1%（可设）
  "max_position_pct": 0.25,        # 单票上限 25%
  "max_open_positions": 5,         # 同时持仓数
  "max_daily_new": 5,              # 每日新开上限
  "portfolio_mdd_kill": 0.10,      # 组合回撤 10% 触发停止新开
  "ai_autonomy": "advise"          # advise=只建议 | approve=建议+需确认 | auto=受控自动
}
```
### 6.2 资金分配
- **风险平价**：每笔固定风险预算 = `账户净值 × risk_per_trade_pct`，`仓位 = 预算 / (入场−止损)`，与现有 F18/G11 一致。
- **相关性降仓**：同一天/同一板块多个信号时，按历史相关性压缩总仓。
- **复利**：`账户净值`每日更新（含浮盈浮亏），后续按净值定仓（复利）。

### 6.3 硬风控（AI 不可违反，防"快速挣钱=爆仓"）
- 单票仓位 ≤ 25%；当日新开 ≤ 5；组合 MDD ≥ 10% → 只平不开。
- 数据不新鲜 / 未到 valid_from / 接近涨停(按板块幅度) → 不买。
- 信号样本过小（该 code 该信号历史 < N 笔）→ 降级为 B 观察，不 A。
- IS 强但 OOS 弱 / 时间 OOS 为负的信号 → AI 默认给低分并质疑（防过拟合幻觉）。

## 八、实现路线（轻量起步，逐步扩展）

### Phase 1（MVP，1-2 天）—— 只读 + 对话 + 决策建议
- `ai_assistant.py`：DataIngest 读 `paper_ledger` + 逐笔回测 + live-prices。
- `JudgeEngine` 三角色（分析师/风控/复盘）打分，输出 A/B/C + 置信度 + 仓位建议。
- `Monitor` 30s 轮询，SL/TP/异常预警。
- `ChatSession` 一个可对话界面（`/ai` 页 + `/api/ai/chat`）。
- 资金模型 + 硬风控。
- **交付**：用户能问"今天买什么"，AI 给出分级、仓位、止损止盈、理由、质疑；能实时盯盘；能复盘。

### Phase 2（3-5 天）—— 策略质疑 + 漏斗 + 决策回溯
- `Feedback` 漏斗异常检测、策略质疑输出。
- 每笔"AI 建议 vs 实际"归档到 `ai_ledger`，自动算 AI 判断准确率。
- **可量化的 AI 价值指标**：AI-A 级胜率 vs 系统全候选胜率（证明 AI 是否真的加分）。

### Phase 3（按需）—— 受控自动
- 当 AI-A 级样本足够且 OOS 稳定 > 规则引擎 baseline 时，开启 `auto` 模式（AI 直接驱动现有执行，但仍有 kill switch）。

## 九、可调整 / 可优化点（预留）

1. **角色权重**：w1..w8 与各角色开关放 config，每周按"AI 判断准确率"调。
2. **打分公式**：可替换为轻量模型（逻辑回归/GBDT 拟合历史"入场后是否到 TP1"，特征 = 画像字段），从规则打分平滑升级到学习打分。
3. **盯盘频率**：60s→30s 可调；可加分钟级 K 线（已有 60m 缓存）判断盘中结构。
4. **对话模型**：接入外部 LLM（DeepSeek/GPT）或本地规则生成；先规则模板（轻量、可控、可审计），再引入 LLM 增强可解释对话。
5. **市场状态**：可挂接正式 regime 模块（广度/指数/行业/流动性）替换现有 `_market_proxy` 近似。

## 十、验收指标（AI 是否有真实价值）

| 指标 | 含义 | 通过线 |
|---|---|---|
| AI-A 级样本胜率 vs 全候选 | AI 是否真的筛出更好的 | A级WR > 全候选WR +5pp（OOS） |
| AI 建议 MFE 达标率 | 入场后是否更快到 0.5R/TP1 | 达标率 ↑ |
| AI-A 级 avg_net | 净收益是否更高 | A级avg_net > 全候选 +1.5pp |
| AI 质疑命中率 | AI 提的"假信号"是否真亏损 | 质疑命中率 > 60% |
| 假信号检出 | 是否提前标记出后验为亏的信号 | 提前标记率 ↑ |
| 资金曲线 | 复利下净值平稳上行、MDD 受控 | 连续观察期合格 |

> **核心反过拟合**：所有 AI 打分规则只能基于"入场时可得的特征"，绝不能用未来 MFE/MAE/收盘价训练或决策（与策略层同一纪律，红线不能破）。

## 十一、与既有系统的关系（隔离与复用）

| 复用 | 不触碰 |
|---|---|
| `core.execution.simulate`（执行语义） | `paper_ledger.json` 结构 |
| `/api/live-prices`（实时价） | `current_scanner_result.json` |
| `handover/最新回测数据`（逐笔回测） | `production_registry.json` 哈希 |
| `config.py`（FEE/SLIPPAGE/MAX_HOLD） | 策略引擎选择逻辑 |
| 前端 nav/CSS | 策略回测/选股逻辑 |

**架构上：AI 助手是"消费者 + 决策建议者"，不是"策略修改者"。** 它的质疑只产出一份 `ai_strategy_feedback.json` 给策略层参考，由策略迭代流程（审计→修复→回测→验证）决定是否采纳。这保证系统稳定、可回滚，同时让 AI 真正倒推策略提升。

## 十二、风险与克制（快速挣钱 ≠ 无风控）

> 目标是"快速完成资本初期积累"——但**快**来自"少亏、只做高置信、复利"，不是"重仓赌"。v1 强制 AI 只能建议，默认 `advise` 模式；连续观察期（Shadow 逻辑 + AI-A 级 OOS 合格）后才升级 `approve`，最后 `auto`。任何阶段都有 portfolio MDD 10% kill switch。
